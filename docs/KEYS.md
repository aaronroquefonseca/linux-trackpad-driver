# Clickable keys

> Generated by `tools/gen_keys_md.py` from `src/proxy.rs` (`key_token_to_code`), `src/config.rs` (`is_known_key`), and `/usr/include/linux/input-event-codes.h`. Do not edit by hand; regeneration or `--check` fails CI on drift.

Every clickable key name: **138 names, 113 distinct codes**. Each row's code is the decimal `EV_KEY` code emitted on the uinput node, with its kernel macro(s) from `linux/input-event-codes.h`.

## Combo syntax

`click_*` / `force_*` accept `+`-joined key names (e.g. `ctrl+c`, `ctrl+refresh`). Names are case-insensitive, surrounding whitespace is ignored, and every segment must be a known key from the table below (`parse_click_action` rejects unknown segments). Combos accept every known key, not just modifiers+letters.

## Mouse-button note

`back` / `forward` are **mouse buttons** (`BTN_SIDE` = 275, `BTN_EXTRA` = 276) -- the long-standing `click_4` / `click_5` mapping. The browser AC Back/Forward keys (`KEY_BACK` = 158, `KEY_FORWARD` = 159) live under the separate `browserback` / `browserforward` names (plus `_`-spelled aliases).

## Deliberately excluded

Mirrored verbatim from the `key_token_to_code` docs -- these
tokens stay unmapped on purpose:

- `KEY_FN` (464): the Fn modifier itself — no standalone meaning.
- `KEY_FN_ESC` (465), `KEY_FN_F1..F12` (466..477), `KEY_FN_1/2/D/E/F/S/B` (478..484), `KEY_FN_RIGHT_SHIFT` (485): driver-internal Fn-row reports consumed inside keyboard firmware/drivers, not meaningful output keys.
- `KEY_PLAY` (207), `KEY_STOP` (128, AC Stop), `KEY_PROPS` (130), `KEY_STOP_RECORD`/`KEY_PAUSE_RECORD` (609/610): obscure duplicates of covered keys (`playpause`/`stopcd`) or record-specific keys no gesture user plausibly wants; emitting them risks confusing mappings.

## Verification

- `tools/gen_keys_md.py --check` regenerates and diffs (CI pin). Unit test `keys_md_pins_generated_table` (`src/proxy.rs`) reads this file and asserts every row matches the live `key_token_to_code` map plus row-count equality, so table drift fails `cargo test`. Every code above was verified against `/usr/include/linux/input-event-codes.h` at generation time; the existing `all_mapped_keycodes_match_kernel_header` test is the standing oracle.
